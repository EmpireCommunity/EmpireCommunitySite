# Changelog

All notable changes to the site are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
and versions follow [Semantic Versioning](https://semver.org/).

Every merge adds its entry under `[Unreleased]`; a merge to `main` never builds an image. The owner decides when a
release happens and which version it gets. The release PR (`chore/release-X.Y.Z`) moves `[Unreleased]` into a dated
`## [X.Y.Z] - YYYY-MM-DD` section; `release.yml` publishes the notes from that section. See `docs/runbook/release.md`.

## [Unreleased]

### Removed

- Leftovers of the old in-repo Worker deploy (T-14e, D-55): the `worker-production` environment and `worker-deploy.yml` workflow-lint rules (and the literal-environment-name rule that existed only to protect that environment; no workflow uses `environment`) with their tests, the `/worker/` line in `CODEOWNERS`, the `worker/` note in `dependabot.yml` and `worker/` in the `AGENTS.md` High list, which now says the Worker lives in its own repository.

### Added

- Docs: the member-count Worker moves to its own repository `EmpireCommunitySite-Worker` and deploys through Cloudflare Workers Builds (D-55, T-14a). ADR-0004 supersedes ADR-0003; `members-json` (2.1, 2.6, 6, 8, 9) and `deploy` (no `worker-deploy.yml`, no `worker-production` environment, new section 12 and an invite-consistency row in the integrity monitor) are rewritten.
- Cloudflare Web Analytics (D-52): the manual snippet (an external module script from `static.cloudflareinsights.com` with `data-cf-beacon` holding the public site token) on every locale page except Apoiar; the root chooser, the 404 and `/discord` have no script at all. The token lives in `site.yaml` (`analytics.webAnalyticsToken`, 32 hex characters, strict schema), not in an environment variable. `check-dist` fails when a locale page does not carry exactly one beacon with only that `src`, `type="module"` and the configured token, and when the support pages, the chooser, the 404 or `/discord` carry any trace of it. Checked in headless Chromium against the built image under the production hardening: the script loads (200) with no CSP violation, and the support pages and `/discord` make no request to Cloudflare Insights.
- Privacy clause 4 now names the community rules page (`/discord`) instead of the Discord redirect page, in both locales and in `docs/content/copy.md`; the legal page interface strings (`legal.version`, `legal.effective`, `legal.toc`) are recorded in `docs/content/copy.md`.
- Terms of Use and Privacy Policy pages (T-13e, D-51), in both locales, from the approved text in `docs/content/copy.md` (`src/content/legal/<locale>/<slug>.md`, version 1.0). Each clause is a heading with an explicit id (`## 1. Title {#id}`), the same ids in the same order in both locales (the build fails otherwise); the page shows the title, the version, an anchored table of contents (sticky on desktop, a list above the text below 1024 px) and the text in one column of up to 68 characters. The effective date is the launch date and is not known yet: `effectiveDate` is optional in the schema and renders nothing while absent (no placeholder date); the build requires it in all four files once `PENDING.legalPages` is false, and `check-dist` warns for each missing one, so the release guard stays shut until the launch PR sets it and flips the flag. Markdown is rendered without raw HTML (a plugin drops every `html` node because Sätteri keeps them verbatim by default; `@astrojs/markdown-satteri` 0.4.7, already in the lockfile as an Astro dependency, is now a direct dev dependency to configure it), with smart punctuation off so the approved text is shown as written; a fixture test proves a `<script>` never reaches the page, and `check-dist` fails on raw HTML in the sources and on a CPF-shaped string anywhere (the tax id is never written in the repository). No text names WhatsApp, donations or a payment provider.
- `/discord` page and discovery files (T-13a, D-29, D-41, D-8). `/discord` is a static page with the community rules in both languages on one URL (pt-BR first, each container complete with its own date, checkbox and join links), in `src/data/community-rules.yaml` (the one source of the text and of `updatedOn`; strict schema, no WhatsApp in any text, the only Discord address allowed is `https://discord.com/terms` as plain text). The join links stay hidden until the container's checkbox is ticked, with CSS only inside `@supports selector(:has(*))` (no `:has()` means they stay visible); no script, form, `<noscript>`, `style=` or refresh; `noindex`, no canonical or hreflang, not in the sitemap; default headers and CSP. The checkbox records nothing and is bypassable by design. The WhatsApp community link is read only by this page (`getDiscordPage`), inside the pt-BR container. `robots.txt` (everything allowed, the sitemap named) and `llms.txt` (English, the en-US pages, no WhatsApp) are built from `routes.ts` and the en-US messages. `check-dist` now checks the page structure, the Terms URL exception (text only, once per container), `rel="noopener noreferrer"`, the gate CSS and the discovery files; `PENDING.discordPage` and `PENDING.discoveryFiles` are false, so the checks block. Cloudflare Web Analytics is not wired yet: it waits for the public token. The `legalPages` pending flag stays true until the Terms and Privacy texts land (the routes build as placeholders until then), so the release guard keeps blocking; `check-dist` warns for each of the four missing legal texts.
- Apoiar / Support us page (T-11), in both locales, in the not-open state (D-28): the goal (R$ 3.000, from `support.yaml`), one `data-donations="not-open"` block, the parts table, how to donate a part (Discord or e-mail), other ways to help and transparency. The site receives no money and shows no way to send any: no payment instruction, account data, Pix key or provider link. `support.yaml` ships with the goal and the part-donation route and `parts: []`; the parts table (P-02) and the progress bar (P-03) appear only when real parts exist, and with no secured value there is no bar and no "R$ 0" (D-39). Reaching the goal switches the progress text and hides nothing (D-22). The schema is strict (a payment field or any `donations.status` other than `not-open` fails the build), totals are derived in integer cents (`src/lib/support-rules.ts`) and `getSupport()` is the only read. `check-dist` now fails when a support page lacks the block, when the block holds anything but the message as plain text, when the page carries an analytics beacon, or when `data-donations` appears on another page; the `supportBlock` pending flag is removed.
- Inner pages (T-9, T-10): Projetos (status legend, the full list with links only for what works, open source), Infraestrutura e servidores de jogos (game servers, request a game, where it runs, our own server) and Organização (how it started, the owner's text, how it works, names, official addresses as a semantic table, contact), in both locales. Founder and Team blocks render only from validated, consented `team.yaml` entries and are absent while the file is empty; an entry with a photo fails the build until photos are rendered. `getTeam` is the only read of `team.yaml`; `check-dist` now fails on a `data-person-id` without an entry or on a name or nickname outside a person block (C-4).
