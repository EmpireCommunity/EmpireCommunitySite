# Changelog

All notable changes to the site are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
and versions follow [Semantic Versioning](https://semver.org/).

Every merge adds its entry under `[Unreleased]`; a merge to `main` never builds an image. The owner decides when a
release happens and which version it gets. The release PR (`chore/release-X.Y.Z`) moves `[Unreleased]` into a dated
`## [X.Y.Z] - YYYY-MM-DD` section; `release.yml` publishes the notes from that section. See `docs/runbook/release.md`.

## [Unreleased]

### Added

- Relay release pipeline and integrity row (B-WK1, D-82, Guindaste). `deploy/members-source/compose.yml` is the relay's compose template, and `scripts/check-relay-compose.ts` (rules in `scripts/lib/relay-compose-rules.ts`, tested) fails CI unless it holds the exact label set with an explicit router priority, no mount, no secret, one public environment key equal to `discord.inviteCode` of `site.yaml`. `release.yml` now builds and checks both images (site and `X.Y.Z-members-relay`) before either is pushed, refuses a tag whose image exists for either, publishes both with their own digest, SBOM, provenance and attestation, and attaches `relay-image-digest.txt`; it fails until the relay `Dockerfile` exists. `scripts/check-relay-image.sh` and `scripts/check-relay-run.sh` check the relay image (base by digest, non-root, 8080 only, no VOLUME, no `traefik.*` label, exactly one added file; 503, 404, 405 and the fixed headers with no network) and run in `ci.yml` as soon as the `Dockerfile` lands. The integrity monitor gains the row "Member count agrees with Discord": it reuses the invite lookup of the Discord entry row, reads only the count and guild id, and a refused lookup only warns.
- Member-count relay script and image (B-WK1, D-82, Forja). `deploy/members-source/relay.mjs`, one file with no dependency, calls the Discord invite endpoint at start and every 6 hours (one retry after 10 minutes, none after a 429) and never because of a request; it keeps in memory only the four fields of members-json 2.11, built field by field after the type checks, and serves them on `GET`/`HEAD /data/members-source.json` (503 until the first good fetch or past 24 hours, 404 for a query string or any other target, 405 with `Allow`, the fixed headers on every status, parse errors included). A failed fetch never ends the process; the only output is one fixed line per scheduled fetch. It refuses to start without a valid `DISCORD_INVITE_CODE` or with a proxy or TLS override in its environment. `deploy/members-source/Dockerfile` adds that one file to the official `node:24-alpine` base pinned by digest, as user `node`, exposing 8080 only. Tested in `tests/relay.test.ts`; `tsconfig.json` now includes the script so the typecheck covers it.
